# Synthetic Borrower Data — rebuilt on real records

This build trains on **UCI Default of Credit Card Clients**, not a hand-written simulator. It learns from real anonymized client records and exports new synthetic client profiles. The beige dashboard and downloadable outputs are included.

## Windows: start here

Extract the ZIP fully. Open the inner **BorrowerData** folder in VS Code. Use 64-bit **Python 3.12** (3.11 also supported). Do not copy an old `.venv` into this project.

```powershell
.\setup_windows.bat
.\start.bat
```

Wait for **Setup complete** before running start. Installation needs internet and may take several minutes. Detailed installation output is saved to `setup.log`. The setup script explicitly selects Python 3.12 or 3.11 instead of blindly using the newest Python version. If no supported Python exists, install Python 3.12 from python.org. If you use the Python install manager, `py install 3.12` can install it.

Open http://127.0.0.1:8501. One local process runs the dashboard and models; no separate backend or manual activation is needed. Keep the terminal open. Stop with Ctrl+C. If “No module named streamlit” occurs, setup did not complete: inspect `setup.log` rather than running a different Python interpreter.

The included trained experiment opens immediately. The original data and checkpoints are bundled, so no data download or training is needed to present the saved result. After dependencies are installed, this works offline.

**This is a full rebuild. Do not replace only app.py in your old simulated-data project.** Core modules, schema, source data, checkpoints and reports have all changed.

## Get the main output: synthetic people profiles

A ready-to-open generated CSV is at **outputs/synthetic_borrowers.csv**. It contains 18,000 fictional client profiles, generated by the latent diffusion checkpoint trained on real records.

In the dashboard:

1. Open **Borrower profiles**. The default table shows generated profiles, with category labels expanded for reading.
2. Select **Latent diffusion** in Inspect generator.
3. Click **Download generated CSV** to export the evaluated batch.
4. To create another batch without retraining, set Fresh profiles and Sampling seed, then click **Generate fresh borrower profiles** and **Download fresh borrower CSV**.
5. Keep the provenance report with the CSV. Fresh batches are explicitly labeled unevaluated; existing charts describe the original evaluated batch.

Each exported row has a generated `synthetic_id`, age, recorded sex, education, marital status, credit limit, six historical repayment statuses, six bill balances, six payment amounts, and a generated default label. There are no original client IDs, names, phone numbers, addresses, income, villages or occupations. No names or attributes are fabricated as if they came from the source.

Synthetic IDs are export identifiers, assigned after generation. They do not enter training. The real source's categorical codes are retained in CSVs, while the dashboard expands documented labels. Some source codes have no definition in the UCI summary; they remain explicitly undocumented.

Official source: https://archive.ics.uci.edu/dataset/350/default+of+credit+card+clients

License: **CC BY 4.0**, https://creativecommons.org/licenses/by/4.0/ . Credit the source and describe your transformations when redistributing adapted source data. Synthetic outputs derive from a model trained on this source; keep the source attribution and generation provenance alongside them.

The public source contains 30,000 Taiwanese credit-card clients, 23 features and a next-month default label. Payment/billing history covers April–September 2005. Monetary units are **New Taiwan dollars (NT$)**, not INR. It is not an Indian rural-household dataset.

Files:

## Evaluation you can defend

35 exact duplicate feature-and-target records are removed **before splitting**. The original source CSV retains all 30,000 rows. The remaining 29,965 unique records are stratified into:

| Partition | Real clients | Role |
|---|---:|---|
| Train | 17,979 | Generator fitting and real-trained classifier baseline |
| Validation | 5,993 | Live dashboard comparisons and development |
| Test | 5,993 | Separate final evaluation after configuration is fixed |

Splits use fixed seeds 42/43 independent of the model-training seed. Original source IDs and identical full records do not overlap across splits. The dataset has no other persistent person identifier, so this cannot prove absence of hidden repeated individuals.

All generators fit on the real training partition. Each makes 18,000 records in the packaged run. Each utility classifier learns only from its own training data. Classifiers use identical balanced logistic regression settings, signed numerical transformation, standardization and one-hot categories. No classifier tuning is performed. PR-AUC is sklearn average precision; F1 and balanced accuracy use threshold 0.5.

TSTR = train on generated records, evaluate on held-out real records. TRTR = train on real training records, evaluate on the same held-out real partition. Validation and final-test numbers are separate. `demo_run/final_test.json` is an already computed test evaluation for the packaged checkpoint. It must not be used for repeated model selection. Live changes do not overwrite that report.

The packaged experiment is one predefined configuration, one model seed and one classifier. Do not claim general superiority, real-world lending readiness or performance for India. In this run the copula beats latent diffusion on predictive utility; the model comparison reports that result rather than hiding it.

## Architecture

Mixed categorical/numeric VAE with learned categorical embeddings; numeric regression and category-logit decoder heads; 12-dimensional latent space. Train the VAE, freeze it, standardize training posterior samples, then train a small MLP DDPM to predict injected noise. Use a 60-step cosine diffusion schedule. Sampling starts from Gaussian noise; decoded categories are sampled from softmax, numerical fields are inverse-transformed, clipped to training bounds and rounded to their source integer precision.

Signed transformation `asinh(x / 1000)` supports the source's negative bill balances. Parameters for subsequent standardization are fitted on training data only. It is not valid to apply the old nonnegative `log1p` codec to these real bill amounts.

Baselines: independent column sampling, a compact empirical Gaussian copula, and VAE prior sampling. The copula is implemented with NumPy/SciPy, not SDV. Category order can affect it. CTGAN is not implemented. Latent diffusion is TabSyn-inspired, not an exact reproduction of TabSyn/FinDiff/TabDDPM.

Objectives:

- VAE: numeric mean MSE + mean category cross-entropy + KL weight × mean latent KL divergence.
- Diffusion: mean squared error between actual Gaussian noise and predicted noise.

Presets: Quick smoke = 5 VAE + 8 diffusion epochs; Presentation = 40 + 60; Extended = 80 + 120. Default latent size 12; KL weight 0.03; model seed 42. More epochs do not guarantee better results. Fresh generation uses a separate sampling seed.

## Metrics and limitations

Numeric fidelity uses KS statistics and training-standard-deviation-scaled Wasserstein distance. Categorical fidelity uses total variation. Marginal error averages numeric KS and categorical TV across all columns, including default. Joint numeric similarity uses Spearman correlation differences. PCA is trained on real training numeric fields only. None of these proves clinical/financial plausibility or individual-record consistency. Monthly charts display six bill balances, not income seasonality or forecasts.

Privacy screening uses numeric range-scaled L1 distance and categorical mismatch, averaged over columns, with equal-size train/validation reference samples (at most 400). Exact-duplicate checks compare generated rows against all training records. No differential privacy, validated anonymization or membership-inference defense is claimed. Demographic fields are modeled for fidelity; no fairness assessment or lending-decision service is included.

## Reproduce

```powershell
.\.venv\Scripts\python.exe train.py --output runs\new_run
.\.venv\Scripts\python.exe generate.py --checkpoint demo_run --rows 1000 --seed 123 --output runs\fresh.csv
.\.venv\Scripts\python.exe -m unittest test_pipeline.py
```

After freezing a new run's configuration, evaluate its test set once:

```powershell
.\.venv\Scripts\python.exe final_test.py --run runs\new_run
```

The script refuses to overwrite an existing final-test report. Do not use successive test evaluations as a tuning loop. Model checkpoints are saved as state dictionaries and loaded with `weights_only=True`; only load checkpoints you trust.

CLI training saves data splits and checkpoints. Browser training remains in session memory; use downloads before closing. All CSV export codes use the meanings in DATA_DICTIONARY.md. Upload accepts the same schema only, with complete rows and unique client IDs; it is not an automatic adapter for unrelated datasets.
